## UI and dashboard specification — P41/P42 design input
The current MainWindow is a startup-only shell, not the final interface. Preserve C# 15/.NET 11/WPF/XAML/MVVM, local-first operation and all existing functional phases. Adopt a modern Arabic RTL desktop shell with collapsible right navigation grouped by workflow, a contextual top bar (site/router/backend, connection state, last update, search), responsive resizable main workspace, reusable XAML resource dictionaries, consistent spacing/typography, light and dark themes, visible focus and keyboard navigation. No fixed-size clipping; test 1024x768, 1280x720, 1920x1080 and high-DPI layouts; virtualized tables with search/filter/sort/paging, clear empty/error/loading states. Navigation groups: overview; sites/routers/monitoring; UM6/UM7/Hotspot/PPPoE; plans/cards/batches/archive/printing; sessions; sales/POS/distributors/accounts/reports; diagnostics/alerts; backup/users/roles/audit/settings. Keep backend-specific features capability-gated; no duplicated screens.
Dashboard: show verified KPI cards (configured routers, reachable vs unavailable/unknown, confirmed cards, uncertain operations, verified active sessions and financial totals only when available). Time series for measured RX/TX throughput in bit/s with consistent units and no interpolation over missing samples; stacked columns for verified distinct card states and batch outcomes; horizontal comparison bars for top routers/plans with explicit period and unit; separate revenue/expense time series with currency and reporting scope. Use donut only for mutually exclusive complete categories; no 3D, arbitrary dual axes or decorative fake metrics. Show timestamp, source, scope, refresh state, sample completeness and tooltips; allow date-range filters and drill-down to actual records; accessible palettes with text/icon redundancy. Unknown/stale is not zero; never fabricate measurements or infer active/expired from ambiguous UM6 fields. Retain raw values for auditing, aggregate/downsample for long periods, bounded background reads and cancellation, no UI thread blocking. Evaluate native WPF rendering and any chart library against x86/x64 .NET 11 compatibility, offline deployment, licensing, RTL, accessibility and measured performance before adding a dependency. Implementation stays in P41/P42 with data contracts built in earlier phases; chart data from P20/P35/P37, not hardcoded production demo data. No web stack. Validate with screenshots at each target size and representative synthetic fixtures, then field data. This is a specification, not completed UI or measured performance.
