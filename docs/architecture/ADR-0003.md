# ADR-0003 — Versioned SQLite and durability (P08)
A frozen SQL migration chain, independent of the changing EF model, is executed through the existing Microsoft.Data.Sqlite provider. No second ORM or production dependency. Schema v1 creates the six baseline entities; v2 adds composite FK lookup indexes. Both versions are internal initial development versions; no previously released v1 database is claimed. An immediate write transaction serializes initialization and upgrades. Application identity and schema version are checked before mutation; unknown populated databases, mismatched identity and future schemas are rejected. DDL and version changes commit atomically. SQLite WAL is selected after migration (outside the transaction), synchronous FULL on each owned connection, foreign keys on, no pooling, bounded command timeout. The caller owns the returned open connection.
DatabaseProbe uses a disposable file and migration chain; no user files. No production data path is selected yet. Legacy EnsureCreated test fixtures are confined to tests; no production creation through EnsureCreated. Future migrations append new steps, never edit an accepted step, add model/constraint regression evidence and pre-upgrade backup policy before real data migration. Do not copy a live WAL database file alone.
Tests cover new initialization, synthetic v1 upgrade, transactional DDL rollback, rejection of unknown/future databases, identity, concurrent initialization, rollback on disposal and real migrated constraints. No power-loss or hard-kill guarantee is claimed; physical crash/fault and disk-full tests and encrypted credential/backup policies remain pending. WAL requires a local supported filesystem; do not deploy on network shares.

## P11 — RouterOS transport foundation decision (2026-11-26)
Official protocol reference: https://help.mikrotik.com/docs/spaces/ROS/pages/47579160/API . Native API is shared by v6 and v7; REST is v7-only and cannot be the common transport. Reviewed https://github.com/danikf/tik4net (Apache-2.0, broad transports/high-level APIs, NuGet distribution) and https://github.com/KCTech-Lab/KC.Tik4Net (Apache-2.0, async .NET 10+, documented v7.21.x low-level tests, no NuGet distribution at review). Both remain references, no source copied. Provisional choice: small original C# byte-framing layer using .NET stream APIs, no external library yet. Reassess if field compatibility/maintenance or feature requirements justify a dependency.
Protocol framing uses canonical big-endian variable-length prefixes and zero termination. Reject unknown/reserved bytes, noncanonical lengths, incomplete reads and bounded 1 MiB word / 4 MiB payload / 1024-word sentence violations. Byte-preserving codec does not assume character encoding; later semantic adapters must choose explicit encoding. Empty received sentences are surfaced to the caller; caller must bound reply counts and command deadlines, dispose connection on any framing/cancellation/incomplete write, and never retry uncertain mutations automatically. No socket or login in this slice. Next: certificate-validated TLS (8729 default, no insecure downgrade), post-6.43 login, typed replies including trap/fatal/empty, deadlines and cancellation, bounded streaming responses, version/package capability tests. v6.49.x and v7 target compatibility only; real device tests pending. No unsupported earlier v6 login promise.

## P11b — Certificate-authenticated TLS transport
Official references: https://help.mikrotik.com/docs/spaces/ROS/pages/47579160/API and https://learn.microsoft.com/dotnet/api/system.net.security.sslclientauthenticationoptions.certificatechainpolicy . Use .NET TcpClient/SslStream with TLS 1.2 or 1.3, required encryption, explicit expected DNS/IP certificate identity, port 8729 by default, no renegotiation and no insecure retry. Platform chain/name/validity/EKU checks are mandatory; no certificate acceptance callback. System trust uses online revocation checks. For isolated offline networks an explicitly pre-provisioned private CA (DER public certificate) may be configured, with CustomRootTrust and no revocation lookup; this deliberate offline mode requires administrator-controlled CA distribution, rotation and revocation outside the client. It does not trust a leaf or automatically accept a peer certificate. Disable automatic issuer downloads; the router must present necessary intermediates. Connection and handshake share one cancellation/deadline budget (15s default, 2min maximum); do not infer bounded DNS or OS chain-validation timing under every platform condition. Dispose failed transports. No credentials sent yet; subsequent command/read/write timeouts and response limits are separate.
Loopback TLS tests with synthetic CA/leaf check valid exchange, wrong host, untrusted root, expired leaf, system trust rejection, cancellation, silent peer, leaf-as-CA and input validation. No production certificate store modifications or real router access. RouterOS v6.49.x requires configured API-SSL with valid certificate and TLS 1.2 support; anonymous DH and plaintext API are intentionally unsupported. Actual RouterOS and Windows x86 physical-device interoperability remain unverified.
