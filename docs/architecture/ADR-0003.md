# ADR-0003 — Versioned SQLite and durability (P08)
A frozen SQL migration chain, independent of the changing EF model, is executed through the existing Microsoft.Data.Sqlite provider. No second ORM or production dependency. Schema v1 creates the six baseline entities; v2 adds composite FK lookup indexes. Both versions are internal initial development versions; no previously released v1 database is claimed. An immediate write transaction serializes initialization and upgrades. Application identity and schema version are checked before mutation; unknown populated databases, mismatched identity and future schemas are rejected. DDL and version changes commit atomically. SQLite WAL is selected after migration (outside the transaction), synchronous FULL on each owned connection, foreign keys on, no pooling, bounded command timeout. The caller owns the returned open connection.
DatabaseProbe uses a disposable file and migration chain; no user files. No production data path is selected yet. Legacy EnsureCreated test fixtures are confined to tests; no production creation through EnsureCreated. Future migrations append new steps, never edit an accepted step, add model/constraint regression evidence and pre-upgrade backup policy before real data migration. Do not copy a live WAL database file alone.
Tests cover new initialization, synthetic v1 upgrade, transactional DDL rollback, rejection of unknown/future databases, identity, concurrent initialization, rollback on disposal and real migrated constraints. No power-loss or hard-kill guarantee is claimed; physical crash/fault and disk-full tests and encrypted credential/backup policies remain pending. WAL requires a local supported filesystem; do not deploy on network shares.
