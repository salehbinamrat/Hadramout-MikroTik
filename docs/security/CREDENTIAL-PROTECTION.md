# P09 — Windows local router credential protection

Use Microsoft System.Security.Cryptography.ProtectedData 11.0.0, Windows DPAPI CurrentUser, to wrap a new random AES-256 key for each field. AES-GCM with 12-byte random nonce and 16-byte tag authenticates the plaintext and binds it to router UUID, field purpose and format version. Only encrypted blobs reach parameterized SQLite commands; pair replacement is one atomic SQL statement. Schema v3 adds router_credentials with a restricted foreign key. Password may be empty, username must not be. Decrypted bytes are returned as a disposable lease; caller must dispose and clear input buffers it owns. Never convert to strings or log input/envelopes/leases. UI and transport are not implemented here; they must observe these boundaries. Encryption is local credential protection, not whole-database encryption or protection from malware running as the same Windows user. Site/router metadata and future voucher secrets need separate review. SQLite deletion is logical; it does not guarantee erasure of old encrypted bytes from WAL/backups. No production secrets are used.

DPAPI CurrentUser normally requires the same Windows account/profile and machine. Portable executable does not mean portable credentials. P10 must define backup/restore behavior explicitly: never silently promise cross-machine recovery; require credential re-entry or an explicitly designed encrypted export/rekey flow. No plaintext export. User-specific access controls and physical different-account/device tests remain pending. Official reference: https://learn.microsoft.com/en-us/dotnet/standard/security/how-to-use-data-protection .
